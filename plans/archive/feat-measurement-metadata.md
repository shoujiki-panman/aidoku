# #56 測定条件を出力へ記録する計画

## 目的

探索・抽出・公開データの各段階に、実際に使った測定条件を残す。
条件が違う結果を同じ集計へ混ぜようとしたら、生成処理を失敗させる。

## 判断

- 探索条件は `crawler/discover.py` の実行時に保存する。抽出時点の現在値を
  後付けすると、古い探索結果へ誤った条件を書くことになるため。
- `prompt_version` は手入力せず、抽出用とオンライン明示用の2プロンプトを
  SHA-256でまとめた値にする。プロンプト変更時の更新漏れを防ぐ。
- 比較する条件から `run_at` は外す。実行時刻が違うだけで比較不能にはしない。
- 既存73件には実行時刻などが残っていない。推測で埋めず `legacy_unknown` とする。
  旧結果だけの公開データは「比較未確認」と明記し、新旧の混在は拒否する。
- `follow` は実際に追ったURL数ではなく、`--follow` を指定したかを保存する。

## 記録する値

- `measurement_version` / `prompt_version`
- `follow` / `max_follow`
- `max_depth` / `beam` / `max_fetches`
- `max_text_chars` / `max_links`
- `model` / `model_version`
- `run_at`

## 実装

1. 測定条件の生成・正規化・互換性判定を小さな純粋関数へ分ける。
2. `crawler/out/*.json` に探索条件と実行時刻を保存する。
3. `extractor/out/*.json` に探索条件を引き継いだ完全な測定条件を保存する。
   条件記録の無い探索結果から新しい抽出結果は作らない。
4. `analysis/export_dashboard.py` が条件を公開JSONへ運び、異なる条件を拒否する。
5. 既存の公開JSONは、過去条件が不明であることを明示して再生成する。

## テスト

- 必須項目がすべて保存される
- プロンプトが1文字変われば版が変わる
- 実行時刻だけ違う結果は比較できる
- `follow`・モデル・探索条件などが違えば拒否する
- 新旧結果を混ぜれば拒否する
- 旧結果だけなら「比較未確認」として出力する
- 探索条件の無い結果から抽出しない

## 完了条件

- 新しい探索・抽出結果だけで、測定条件を後から復元できる
- 公開JSONに条件と各実行時刻が残る
- 条件の異なる記録を同じ集計へ混ぜられない
- 過去73件の不明な値を推測で埋めていない

## 実施結果

- 新しい探索JSONが探索条件と実行時刻を保存する
- 新しい抽出JSONがプロンプト版・追従指定・上限・モデル・実行時刻を保存する
- 記録の無い古い探索JSONから新しい抽出結果を作らない
- 公開JSON生成時に条件差と新旧混在を拒否する
- 既存73件は `legacy_unknown` と明記し、値は推測で補完していない
- 公開3手続きの点数・抽出内容は変更なし
- Node 78件＋Python 192件、計270件 PASS
