# #9 「今やる1件」実装計画

方向づけ: 2026-08-17 に本人と再確認。AI読を閲覧中心のダッシュボードではなく、
行政サイトをAIに読める状態へ保つ小さな保守エージェントへ進める。
その最初の1PRとして、点数の閲覧で終わらせず**利用者がその場で1件の改善へ進める**画面にする。

- Issue: #9「点数だけで、どこから直すか分からない」
- branch: `feat/next-action`（base: `origin/main` `7125206`）
- **1 PR = 1目的。** URL入力・定期実行・通知・MCP・全面デザイン変更は含めない

## 何を作るか

`index.html` の最上段（案内バナーと手続きタブの直後）に **「今やる1件」** を1枚だけ出す。

利用者が受け取るもの:

- 自治体・手続き・読めなかった項目
- なぜこの1件なのか（選定規則をそのまま書く: 見込み効果が最大の読めなかった項目）
- 現在の結果と、改善した場合の見込み効果（total → total+gain）
- 公式ページURLと測定日時（`legacy_unknown` で時刻が無い場合は「記録なし」と正直に出す）
- 担当部署へ渡せる短い依頼文（コピー可能。**自動送信はしない**）
- 状態チップ: 現データはすべて `未検証の提案`（実サイトでの再測定まで確定と言わない）
- 再確認の方法（METHOD.md §5 の再現コマンドに自治体ID・手続きIDを埋めたもの）

既存の全体集計・比較・一覧・詳細は**補助情報としてそのまま下へ残す**。

## 選定規則（実装時に勝手に賢くしない）

現在選択中の自治体・手続きの `improvements` を

1. `gain` 降順
2. 同点は `web/data/fact-types.json` の定義順（`fact_types` → `extra_measures`）
3. それでも同じなら `field` の文字列順

に並べた**先頭1件**。全自治体横断の「今日の1件」は次PR。

## データ源

既存 `web/data/scores-*.json` の `improvements[].field / gain / reason`、
`total` / `page_url` / `measurement`。数値・文言をHTMLへベタ書きしない。
`improvements` が空配列（全項目読めた区）は「今やる1件はありません」と出し、
見本数字や架空の改善案を出さない。

## 実装の形

| ファイル | 何をするか |
|---|---|
| `web/assets/next-action.js` | 選定 `pickNextAction()` と依頼文組み立て `buildRequestText()` の Pure Function。DOMに触らない。node からも読めるようにする |
| `web/test_next_action.mjs` | 正常系・同点・欠損・空配列・不正型・未知の項目名のテスト |
| `web/assets/app.js` | `select()` から「今やる1件」を描画。コピーはボタンで（自動送信なし） |
| `web/index.html` / `web/assets/app.css` | 最上段に1枚。デジタル庁デザインシステムの既存作法内 |
| `.github/workflows/test.yml` | node テストの glob に `web/test_*.mjs` を足す |
| `STATUS.md` | この変更を反映 |

## 言わないこと（画面にも書かない）

- 「この修正で必ず直る」（再測定前）
- 「実サイトを直した」「改善確認済み」（本番で再測定していない）
- 「本物のAI来訪があった」（署名つき来訪は0件）
