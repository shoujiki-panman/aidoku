**5W1H・KPI表（現状値→目標値→測定方法）・受け入れ条件**の3つだけ借りた。

## Why — なぜ要るか

18日測って住民に届く点は上がった（転入 59.6→63.9 / 児童手当 45.7→51.3 / 粗大ごみ 39.6→53.9）。
だが 2026-09-07 に数えたら:

- **入力欄は `web/` 全11枚で 0 個**（`<input>` も `<textarea>` も無い）
- star 0 / fork 0（作成 2026-07-26）

測る道具は増えたが、**区の担当者が自分の文面を持ち込める面が無い**。
見るだけの資料であってアプリではない、というのがここの中身。

## Who / What

| | |
|---|---|
| 使う人 | 区の担当者。自分の区の1ページを直そうとしている人 |
| 入れるもの | 区・手続き（選ぶ）＋ **直した文面**（書く） |
| 返るもの | 必須要素のうち**埋まっていないものの一覧**と、埋めた後の**見込み点** |
| 動く場所 | GitHub Pages（静的）。サーバーを増やさない |
| いつ | B2（穴の一覧と埋める欄）→ B3（もう一度叩く導線）の順 |

## KPI

| 指標 | 現状値 | 目標値 | 測定方法 |
|---|---|---|---|
| 入力欄の数 | **0** | 1画面に1つ以上 | `grep -c "<input\|<textarea" web/*.html` |
| 文面を書いて見込み点まで行ける手続き | **0** | 3手続き × 23区 | `fix.html` を開いて実際に通す |
| 必須要素を出せる自治体 | **3**（golden のある区だけ） | 23 | `scorer/golden/*.csv` のスロット名を畳んだ数 |
| 外部の利用 | star 0 / fork 0 | **目標を置かない**（測るだけ） | `gh repo view` |

## 受け入れ条件（これが全部通ったら完成）

1. 区と手続きを選ぶと、その手続きの**必須要素が全部並ぶ**（埋まっている／いないの別つき）
2. 埋まっていない要素それぞれに入力欄があり、文字を入れられる
3. 空のまま「見込み」を押すと、増える点は **0 のまま**
4. 入れた文が必須要素の語を含むと、その要素が「埋まった」に変わり、見込み点が増える
5. 増える点が `10×(伝わった必須要素数 ÷ 必須要素数)` と一致する（`scorer/score.py` と同じ式）
6. **入れた文はどこにも送られない。** 押しても増える通信が 0 本（DevTools で確認する）
7. 「推定であり行政機関の公式発表ではない」が画面に出ている

## 制約 — 既存の決定と衝突させない

- **公開の判定APIは作らない。** `decisions/api-layer-from-michiyomi.md` の通り、誰でも叩ける
  `/v1/score` は他人がこちらのアカウントで LLM を走らせる口になる。
  よって**この画面は LLM を呼ばない**。必須要素の文字列照合だけで①〜⑦は全部満たせる
  （点の式が決定論的なので、LLM が要らない）
- LLM が要るのは「未測定のURLをその場で測る」B3 の方。そこは手元の `claude -p` に渡す
  コマンドを出すに留める（`gennai_app/server.py` は既にあるが localhost）

## 分かっていない一番大きなこと（最初の一手はここ）

必須要素のスロット名は3自治体を通してほぼ共通だった（2026-09-07 に数えた、必要書類の場合）:

| 手続き | スロット名の種類 |
|---|---|
| 転入 | 5（本人確認書類 / 前住所地からの持参書類 / 外国人住民の追加書類 / 代理人が届け出る場合 / 該当者限定・数量の条件） |
| 児童手当 | 7 |
| 粗大ごみ | 4 |

**ただし表記ゆれがある。** 児童手当には `個人番号と身元の確認書類` と、
`個人番号確認書類`＋`身元確認書類` の両方が出てくる（同じことを1スロットと2スロットで書いている）。

golden は3区分しかないが、それは**値**（その区に実際に書いてある文）の話で、
**スロット名（何を書くべきか）は手続き共通に畳める。** 畳めれば 23区に出せる。
畳めるかどうかを確かめるのが最初の一手で、**それが駄目なら KPI の「23」は達成できない**。

## やらないこと

- **記事の移行要件・運用要件・非機能（性能/信頼性/拡張性）は書かない。**
  利用者0・静的サイト・データ1MB弱で、書いても守る相手がいない。
  借りたのは 5W1H・KPI表・受け入れ条件の3つだけ
- **画面を増やさない。** 3枚（`index` / `board` / `fix`）のまま `fix.html` に足す
- **値をこちらで埋めない。** 現行の `fix.html` が「値はこちらでは埋めません」と書いている方針は
  変えない。埋めるのは担当者で、こちらは**穴の場所と、埋まったかの判定**だけを出す
