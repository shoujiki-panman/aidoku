# 「記載なし」と「見に行っていない」を分ける

Status: 計画（検出まで実装、挙動の変更は未着手）
関連: [`plans/read-through.md`](read-through.md)（この計画を生んだ追試） / Issue #148 / `METHOD.md` §6

## 問題

読み取り器は、項目が取れなかったとき `failure_reason: "記載なし"` と答える。
だが 2026-08-27 の追試で、**その「記載なし」の中に「見に行っていない」が混ざっている**ことが
実データで確定した。

転入届・24自治体の実測:

| | |
|---|---|
| AIがリンクを**1本も開かなかった**自治体 | **14 / 24** |
| 上限（`MAX_FOLLOW = 2`）に当たった自治体 | 7 / 24 |
| 追従した本数の合計 | 17本（上限まで使えば48本） |

**上限の問題ではない。** AIが「もう十分だ」と判断して、開かずに「記載なし」と答えている。

### 実害が出た3区

追試（`analysis/reread_field.py`）で読み落としが確定した3区は、
**そのまま「4項目すべて記載なし」と答えていた区**だった:

| 区 | 追従 | 読み取り器の答え | 追試の結果 |
|---|---|---|---|
| 世田谷区 | **0本** | 4項目すべて記載なし | 窓口が書いてあった |
| 墨田区 | 1本 | 4項目すべて記載なし | 必要書類・期限・窓口が書いてあった |
| 中央区 | 2本 | 4項目すべて記載なし | 必要書類・期限・窓口が書いてあった |

そして探索台帳（`analysis/read_ledger.py`）で照合すると、
**答えのあったページ5件はすべて `shown_not_chosen`** ——
つまり **AIに渡したリンク一覧に載っていたのに、開かなかった。**

```
中央区    [22] 引越しワンストップサービスの利用
中央区    [18] 住所変更の届出を忘れずに
墨田区    [18] 引越しワンストップサービスが始まりました
墨田区    [14] 住民登録の届出
世田谷区  [13] お引越し手続きのご案内（総合支所くみん窓口）
```

## なぜ致命的か

`METHOD.md` §6 は「当日踏んではいけない表現」に **「4項目とも0点の18セルを
『その区が書いていない』と言うこと」** を挙げている。禁止していたのは正しかった。
**今回、その18セルのうち3件について、実際に書いてあったことが確認された。**

`web/data` は `verdict: "読めない"` としか書いていないので誤りではない。
だが **「読めない」の理由が区の側にあるように読める。** そこを分ける。

## 訂正（2026-08-28）— ①の仮説は間違っていた

「AIが開かずに『記載なし』と答える」を原因だと書いた。**A/Bで否定された。**

`analysis/try_follow_prompt.py` で、児童手当の7区（公開データでは全項目「記載なし」・追従0本）に
**旧プロンプトのまま**同じ入力を与えたところ:

| | 記載なし | リンク提案 |
|---|---|---|
| **公開データ**（7区×4項目=28件） | **28/28** | **0件** |
| 今日の**旧**プロンプト | **14/28** | 16件 |
| 今日の**新**プロンプト | 9/28 | 19件 |

**同じプロンプト・同じページで、記載なしが半分になった。**

だから原因は「AIが開かない」ではない。

> **あの日のAIはそう答えた。今日のAIは違う答えを返す。そしてどのAIだったか記録が無い。**

公開データの `measurement` は `legacy_unknown` で、**`model_version` すら null**。

### これが意味すること

**公開している「読めない」の一部は、いま同じ条件で測り直しても再現しない。**
道具の欠陥ですらなく、**記録の欠落**である。
`measurement_signature` を作った動機そのものが、公開済みデータには適用されていない。

`METHOD.md` §6 が「4項目とも0点の区を『その区が書いていない』と言うこと」を
禁じていたのは、いよいよ正しかった。理由が1つ増えた——**再現しないから。**

### それでも案Aは残す

再現性の問題とは別に、プロンプトの修正には効果があった:

- 「記載なし」 14 → 9
- 理由と `follow_urls` が食い違う矛盾 **2件 → 0件**
  （旧プロンプトは `記載なし` と言いながらリンクを提案していた。
  **本番ならこの2件は `ValueError` で落ちる**）
- 反転したのは千代田区の手数料、北区の手数料、**墨田区の必要書類・窓口・期限**。
  追試（#155）で「書いてある」と確認済みの区がそのまま反転した

### 次にやること（順番が変わった）

1. ~~③挙動を直す~~ → **プロンプトの修正は入れる**（矛盾2件が消えるだけでも価値がある）
2. **`model_version` を含む条件つきで測り直す。** これが本丸になった。
   再測定しないかぎり、公開データのどの数字も「その区が書いていない」とは読めない
3. ②公開データに理由を出す — 再測定と同時にやる
