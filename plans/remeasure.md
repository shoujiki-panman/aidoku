## なぜ要るか

2026-08-28、公開データが**再現しないこと**が確定した。

児童手当の7区（公開データでは全項目「記載なし」）に、**旧プロンプトのまま**同じ入力を与えた:

| | 記載なし | リンク提案 |
|---|---|---|
| **公開データ**（7区×4項目=28件） | **28/28** | **0件** |
| 2026-08-28 の旧プロンプト | **14/28** | 16件 |

同じプロンプト・同じページで半分になった。
公開データの `measurement` は `legacy_unknown` で、**`model_version` すら `null`**。

> **どのAIが出した数字か、記録が無い。**

`measurement_signature` を作った動機そのものが、公開済みデータには適用されていない。
**再測定しないかぎり、公開データのどの数字も「その区が書いていない」とは読めない。**

## この再測定で何を固定するか

`CONDITION_KEYS` 15項目すべて。特に:

| キー | 値 |
|---|---|
| `model_version` | 実際に呼んだモデル |
| `prompt_version` | プロンプト2本の sha256（#159 の修正を含む） |
| `read_breadth` | `agent_pick` |
| `non_html_reading` | `none` |
| `link_order` / `table_reading` | `score_desc` / `heading_value` |

**条件が違う記録どうしは比較を拒否する**（`attribution()` が unknown を返す）ので、
旧データと新データは自動的に別物として扱われる。**混ざらない。**

## 探索はキャッシュの再生である（重要）

`crawler/discover.py` を回し直したが、**713件中615件がキャッシュから返った**（4分50秒）。
つまり **ページの中身は当時のスナップショットのまま**。

これは狙いどおり:

- **区のサーバーに同じものを取りに行かない**（行儀）
- **変数がモデルとプロンプトだけに絞れる。** ページが変わっていたら何が効いたか分からない

**言えること**: 同じページに対して、条件を記録したうえで測るとどうなるか
**言えないこと**: 今日の区のサイトがどうなっているか（それは別の測定）

## 対象は24自治体（探索は28ある）

`crawler/targets.json` には町田・三鷹・武蔵野・東京都も入っているが、
**抽出は一度もされていない**。公開データと比べられるよう **24自治体に揃える。**
広げるのは比較が済んでから。

## 6区ずつ4回に分ける

`extractor/batch.py` の `build_batch` は**全件を作ってから書く**（途中失敗で既存出力を
壊さないための設計）。正しいが、24区一括だと **落ちた瞬間に全部消える。**

利用上限で71ページを失った実績があるので、**6区ずつ4バッチ**に切る。
1回落ちても失うのは6区ぶん。

```
1  adachi arakawa bunkyo chiyoda chuo edogawa
2  hachioji itabashi katsushika kita koto meguro
3  minato nakano nerima ota setagaya shibuya
4  shinagawa shinjuku suginami sumida taito toshima
```

旧結果は `analysis/out/remeasure/` に退避してある（比較用）。

## やらないこと

- **公開データ（`web/data`）をこの段階で書き換えない。** 差分を見てから決める
- **判定基準を動かさない。** 必須要素は人が決めたまま
- 児童手当・粗大ごみは後。まず転入届で通し方を確定する
- **4自治体を足さない。** 比較が済むまで母数を変えない
