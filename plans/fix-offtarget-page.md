# #86 対象ページと確認できない区へ改善依頼文を出さない

- Issue: #86
- branch: `fix/offtarget-page`（base: `origin/main` `a1167de`）
- **1 PR = 1目的。** 測り直しそのもの・クローラーの改良・URL入力は含めない

## 何が起きているか（実データで確認済み）

PR #85 で入れた「今やる1件」は、4項目すべて読めなかった区にも、**区名つきの改善依頼文**を出す。
しかしその区の多くは、こちらが**対象の手続きのページに着けていない**。

公開3手続き69組のうち **4項目とも読めないのは18組**。そのうち **17組**は、
判定AI自身が `page_notes` に「別の手続きのページ」「索引・ハブページ」と書いている。

| 例 | 採点したページの実際の中身（`notes` より） |
|---|---|
| 墨田区・転入届 | 「転入届・転居届と併せて行う電子証明書発行の同一世帯員代理手続き」の説明 |
| 台東区・児童手当 | 石浜橋場こども園の預かり保育の案内（児童手当と無関係） |
| 足立区・粗大ごみ | 粗大ごみの資源化実績・推移の統計ページ |
| 世田谷区・転入届 | 「戸籍・住民登録等」の目次（カテゴリ一覧） |

この状態で出る依頼文は「このページに必要書類を書き足してください」。
**受け取った職員から見て誤りであり、こちらの到達失敗を相手の不備として通知している。**

`METHOD.md` §4-7 は「0点のうちどこまでが道具の制約かは、切り分けていない」と既に自認している。
切り分けていないものを、区名つきの依頼文にして公開してしまっていた。

## 判断

- **4項目が1つも読めない場合、「区のページに書かれていない」と「こちらが別のページを採点した」を区別できない。**
  区別できないものを、区への依頼にしない
- ただし `notes` の日本語を機械で読み取って「別ページだ」と判定しにいかない。
  **構造的な条件（読めた項目が0）だけで決める。** 文面の解釈で当てにいくと外れたときに気づけない
- 断定もしない。ラベルは「対象ページに着けたか**確認できていない**」。
  こちらが確認できていないという事実だけを言う
- 江戸川区・粗大ごみのように `notes` が空の組もある。**空でも同じ扱い**にする（0/4という条件だけで決めるため）

## 実装

### 1. `analysis/export_dashboard.py`

各自治体へ `page_status` を足す。判定は Pure Function。

```json
"page_status": {
  "code": "target_unconfirmed",
  "label": "対象ページに着けたか確認できていません",
  "detail": "4項目が1つも読み取れませんでした。区のページに書かれていないのか、こちらが別のページを採点したのかを、この結果からは区別できません。"
}
```

読めた項目が1つ以上あれば `code: "facts_found"`。
`オンライン明示` は 4項目に含めない（`full_marks` と同じ扱い）。

公開JSON `web/data/scores-*.json` は**手で書かず、このスクリプトで再生成する**。

### 2. `web/assets/next-action.js`

`decideNextAction(muni, factOrder)` を足し、`kind` を返す。

- `page_status.code === 'target_unconfirmed'` → `kind: 'remeasure'`。
  **依頼文を作らない。** 宛先はこちら側で「対象ページか確認して測り直す」
- それ以外で `improvements` に候補あり → `kind: 'ward_request'`（現行どおり）
- 候補なし → `kind: 'none'`

`pickNextAction` / `buildRequestText` は変えない（テスト済みのため）。

### 3. `web/assets/app.js` / `app.css`

`kind` で出し分ける。`remeasure` のときは

- 「今やる1件（**こちら側**）: このページが対象の手続きのページか確かめて、測り直す」
- 採点したページのURLと、判定AIの観察記録（`notes`）
- 再測定コマンド（既存の `buildRecheckCommand`）
- **区への依頼文は出さない**

### 4. `web/data/README.md`

`page_status` の意味と、`target_unconfirmed` が「区の不備」ではないことを明記する。
