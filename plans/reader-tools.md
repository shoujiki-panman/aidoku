# 読めないものを読む道具（MulmoClaude 型の追加ツール）

Status: 設計（未実装）。**First Stage 通過後**
関連: [`plans/measurement-harness.md`](measurement-harness.md)、[`decisions/measure-to-tool.md`](decisions/measure-to-tool.md)

## 考え方

自治体に「直してください」と頼んで待つのではなく、**読めない形のものを読む道具を
こちらで作って住民に渡す**。MulmoClaude の「追加ツール」（MulmoCast / Vision /
Bridge CLI / Slack Bridge を差し込む形）と同じ構成にする。

判定の本体は触らず、**取得と読解の前段に道具を差す**。道具ごとに版を持ち、
どの道具で読んだかを測定条件（`measurement_signature`）に残す。

## 何が読めていないのか（68セルの観察記録を数えた）

| 読めない理由 | セル数 | 要るもの |
|---|---|---|
| **リンク先にある** | **30** | 道具ではなく、渡すリンクの上限と並べ方 |
| PDFの中 | 7 | **PDFを読む道具** |
| 表の中 | 5 | **表を読む道具** |
| 目次で止まった | 4 | 対応済み（AIが選ばなかった扉を住民に渡す・#136） |
| 条件分岐が多い | 2 | 判定側の課題。道具では解けない |

探索が見つけた候補のうち **PDF は 60件**。無視している量としては大きい。

## いちばん効くのは道具ではない

**30セルは「答えはリンクの先にあるのに、そのURLを渡していない」**。
`extractor/fact_extract.py` の `MAX_LINKS = 40` で本文のリンク一覧を打ち切っており、
地域ナビゲーションで埋まって本命が入らない。`MAX_FOLLOW = 2` も効いている。

**先に上限と並べ方を直す。** 道具を4つ足すより、ここ1箇所のほうが効く。
並べ方は `crawler/discover.py` の `score_link` が既に持っているので、
リンク一覧を渡すときも同じ点数で並べ替えれば済む。

## 道具にする単位

| 道具 | 役目 | いまの扱い |
|---|---|---|
| **PDF読み** | 添付PDFから4項目を取る | `is_non_html_url` で弾き、`failure_reason=PDF内のみ` にしている |
| **表読み** | 条件つきの表（国内転入／国外転入など）を行ごとに読む | 本文として渡していて、条件が潰れる |
| **JS描画** | スクリプトでしか出ない本文 | 未対応（件数は未計測） |

道具は**差し替え可能**にする。`--tools pdf,table` のように選び、
どの道具を使ったかを測定条件に入れる。道具を足したら点が上がった、が
「サイトが直った」に見えないようにするため。**これは必須**。

## やらないこと

- **判定そのものを道具にしない。** 4項目の必須要素は人が決める。
  道具は「読めなかったものを読む」だけで、値は作らない。
- **PDFの中身を再配布しない。** 読み取って点を出すだけで、本文は持たない
  （いまの `quote_withheld` と同じ扱い）。

## 順番

1. `MAX_LINKS` と並べ方を直す（30セル）← 道具より先
2. PDF読み（7セル）
3. 表読み（5セル）
4. 手続きを増やすときに、道具を差し替えられる形にしておく
   （免許更新のように、様式が違うものを足す前提）
