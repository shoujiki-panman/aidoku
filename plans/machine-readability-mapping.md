# AI読の指摘を「行政データにおける機械可読性に関するルール」に対応づける

Status: 実装済み（`analysis/mr_mapping.py` + テスト13件）
関連: [`plans/jis-mapping.md`](jis-mapping.md)（JIS X 8341-3 側の対応づけ） / Issue #148

---

## なぜ要るか

2026-08-31、デジタル庁「データマネジメント研修」（2026/08/28・Fact & Data Unit）を読んだ。
**AI読が測っていることが、国の枠組みに正面から入っていた。**

> 「AIが安心して学習・推論に使えるデータを **AI-Readyデータ** と呼ぶようになった」（p.14）
> 「AI時代にはシステム間の相互運用性だけでなく、**AIとシステムの間の相互運用性も課題**」（p.48）
> 「社内ドキュメントなどの非構造化データは元々人間向けに作られているため、
> **AIが読み込めない、あるいは非効率にしか読めない場合がある**」（p.49）

そして**判定ルールと判定ツールが既に公開されている**ことも分かった。

| | |
|---|---|
| ルール | **行政データにおける機械可読性に関するルール**（令和8年3月31日・各府省庁DX推進連絡会議） |
| 形式 | **30ルール**（Level1:15 / Level2:6 / Level3:9）。**CSV / JSON で機械可読に公開** |
| ツール | **Harunobu（春信）** MIT。AIなしの決定論的判定。100点満点でレベル別採点 |

JIS の対応づけ（`plans/jis-mapping.md`）と同じことを、この新しいルールでもやる。
**これは JIS より近い。** JIS は「人が読めるか」、こちらは**最初から機械・AI向け**である。

## 実際に動かして確かめたこと（2026-08-31）

Harunobu を入れて、**大田区が公開している粗大ごみ品目一覧（`.xls`）で試した。**

```
UnsupportedFormatError: .xls 形式はサポートされていません。.xlsx に変換してください
```

**国の判定ツールが、区の公開ファイルを読めない。** ルール L1-01 の許可形式
（xlsx / CSV / XML / ODF / JSON）に `.xls` は含まれていないので、判定以前に落ちる。

AI読は同じファイルから **15,804字**を読んだ（`crawler/xls.py`）。

> ⚠ **`crawler/xls.py` はこのブランチにまだ入っていない。** 2026-08-30 に実装・コミット
> したが、作業ディレクトリ（`~/Documents` 配下）へのアクセスが OS の権限で塞がれ、
> push できていない。許可が戻り次第、この下に積む。
**判定の前段が塞がっていたので、そこを開けた**という位置づけになる。

正常な `.xlsx` では 30ルールが1件ずつ合否・重大度・信頼度つきで出ることも確認した。

## 対応づいたもの（実測つき・2件）

| ルール | AI読の指摘 | 実測 |
|---|---|---|
| **L1-01**（FATAL） | 答えが PDF / Word にしかない | 非HTML候補81本（PDF76・Word3・Excel2）。うち10本は誰にも読めない |
| **L1-01**（FATAL） | 古い `.xls` で公開 | Harunobu は読み込み拒否。AI読は15,804字読了 |
| **L3-08**（MINOR） | いつ時点の情報か分からない | パスポート手数料 6/6 が改定前の額。3回は今日の日付つき |

**30ルール中2件しか対応づかない。** 少ないことを隠さない（テストで10件未満を強制）。

## 対応づかないもの ＝ AI読の固有部分

★JISのときと同じで、**ここを書かないと何が新しいのかが消える。**

| AI読が測っていること | 実測 | なぜルールで測れないか |
|---|---|---|
| 答えが**どこにも書かれていない** | 74項目（手数料37・期限19・必要書類12・窓口6） | ルールは**既にあるデータの形式**を測る |
| 答えのページに**たどり着けない** | 候補の44〜56%はAIに一度も見せていなかった | ルールは**1ファイル単位**。ページ間の到達を見ない |
| **読めるPDFと読めないPDFの区別** | PDF76本中、対応表が無い5本・画像3本は外部変換器でも0字 | ★ルールは「**PDFは不可**」で止まる。現実には区はPDFを出し続ける |
| **AIの判定そのものの揺れ** | 再現性が手続きにより7倍違う（3.1% / 12.5% / 21.9%） | Harunobu は決定論的（AIなしで動く）。揺れは生じない |

**3つ目が今回いちばん重い。** ルールは「PDFをやめろ」と言う。AI読は
**やめられていない現実で、住民のAIが実際に読めるかどうか**を測っている。

## 立ち位置（1枚で言うと）

```
Harunobu（デジタル庁）   形式が整っているか   Excel / CSV    決定論的に採点
AI読                     答えに辿り着けるか   Webページ全体  AIに読ませて実測
```

**重ならない。** 今日の JIS 実測（alt 0/1128・リンク題4.2%/2.7%・見出し1.8%）が
これを裏づけている。**形式のルール適合だけでは、AIが答えに届かない理由は説明できない。**

## やらないこと

- **Harunobu を作品本体に組み込まない。** 標準ライブラリのみの方針を変えない
  （`plans/decisions/external-reader.md` と同じ扱い。使うなら検算・比較のみ）
- **30ルール全部に無理やり対応づけない。** 実測のあるものだけ載せる

## 次にやれること

- 区が公開している Excel / CSV を集めて Harunobu で採点し、**AI読の点数と並べる**
  （形式の点と到達の点が、同じ区でどう違うか）
- `.xls` → `.xlsx` 変換を挟めば Harunobu にかけられる。`crawler/xls.py` が入口になる
