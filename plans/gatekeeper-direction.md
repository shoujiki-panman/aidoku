## めざす役割：AWSのサポート役（Trusted Advisor）の自治体サイト版

置いておくと、勝手に見ていて、問題を見つけたら教えてくれる。

## 大事な線（ここを外すと作品ごと崩れる）

### ❌ 他人（自治体）のサイトに黙って設置することはできない

- **技術的に無理**：門番はサイトの持ち主がサーバーに入れて初めて動く。区のサーバーには入れない
- **やってはいけない**：他人のサイトの通信に無断で割り込むのは不正アクセス

「仮面調査員」の狙い（本物のエージェントがどう来るか見たい）は正しい。
ただし**設置場所を他人のサイトにしてはいけない。** 下の合法な形で同じ狙いを満たす。

## 測ることを2つに分ける

| | タグ（門番の設置）が要るか | 誰のサイトでも測れるか |
|---|---|---|
| **① 採点**：ページがAIに読めるか（必要書類・期限・手数料が読み取れるか・構造化データ・情報到達） | **要らない。外から取って測れる** | ✅ どの区でも |
| **② 来訪観測**：誰が・何を聞いて・取れずに帰ったか | **要る（サーバー側の情報）** | ⚠️ 自分が持っているサイトだけ |

**① は今の AI読が半分やっている。** これは「タグ埋設なしで測れたら理想」の答えそのもの。
**② は門番が要る。** そして他人のサイトには置けない。ここが制約。

## 招待メールを待たずに「本物のエージェントの来かた」を観測する手順

Cloudflare の招待（8/8ごろ・受諾期限3日）が来なくても、これはできる。合法。

1. **区の転入届ページのコピーを1枚、自分のドメインに置く**
   （`shoujiki-panman.github.io` 等。自分のサイトなので設置は自由）
2. **その前に門番を立てる**（自分のサイトなので合法）
3. **自分で ChatGPT / Claude / Perplexity に「このページで転入届の手数料を調べて」と頼む**
4. そのエージェントが実際にどう来るかが門番に残る：
   - 署名して来るのか（Web Bot Auth を出すのか）
   - User-Agent は何か
   - HTMLを取るだけか、`/ask` のような窓口を探すのか
   - robots.txt を見るか

**これで B の一番知りたいこと「本物はどう来るのか」が実データで分かる。**
タグを他人のサイトに埋めず、本物のエージェントを観測できる。

### この観測で分かること次第で、門番の価値が決まる

| 観測結果 | 意味 |
|---|---|
| 署名して来る | 門番が捕まえて記録できる。B が成立 |
| 署名せず User-Agent だけ | 記録はできるが「どのAIか」の確度が落ちる。設計変更が要る |
| HTMLを取るだけで窓口を探さない | `/ask`・`/mcp` は当分使われない。門番は「観測」に振る（答えを返す機能は将来用に温存） |
| robots.txt / llms.txt を見る | サイト側が用意すべきものが分かる＝採点項目に足せる |

**いまの門番は「窓口を叩きに来る」前提で作ってある。** もし実際は「HTMLを取るだけ」なら、
門番の主役は「答えを返す」ではなく「来訪を観測して、取れなかったものを推定する」になる。
→ **観測してから決める。想像で作らない。**

## いまのコードで既にできていること（実物確認済み）

`gatekeeper/worker.mjs` を読んで確認：

- 署名つきエージェント → 検証 → 記録 → 整った答えを返す ✅
- 署名なし（人間） → 記録せず素通し（住民のデータを集めない）✅
- 検証失敗 → 記録だけして素通し（門番は拒否しない）✅
- 偽の名乗り対策：検証成功時だけ `agent` を記録（他人の公開 keyid は誰でも書けるため）✅
- 1つの門番が複数サイトの前に立てる設計（キーが `host+path`）✅

**土台はある。足りないのは「本物で試していない」ことと、下の安全対策。**
