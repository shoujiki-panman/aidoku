# 表を、本文の平文として渡すか、行ごとに「見出し: 値」へ組み直して渡すか

Status: 決定済み（2026-08-23）
Tracks: crawler/htmlutil.py / extractor/fact_extract.py / measurement.py / analysis/probes/check_tables.py

## 問題

自治体のページは、必要書類・手数料・期限を `<table>` に入れていることがある。
`crawler/htmlutil.py` の `parse()` は `td` / `th` / `tr` を改行にするだけなので、
セルの文字は本文に入っているが、**どの見出しの列の値かは消える**。

港区・転入届がそのまま出ている。必要書類が「国内転入」と「国外転入」の
**2つの表に分かれ**、AIには「転出証明書」「前の住所地の市区町村で…」が
ただの行として並んで届く。実測の `page_notes` にも
「別テーブルに分かれ条件分岐が多い」と本人が書いていた。

これも自治体のページの問題ではなく、**こちらの渡し方の問題**（blame = ours）。

## 決定

`crawler/htmlutil.py` に表を読む純関数を足し、
行ごとに `【行の見出し】列の見出し: 値 / 列の見出し: 値` の1行へ組み直して、
`extractor/fact_extract.py` が本文とは**別立ての節**でAIへ渡す。

- **標準ライブラリのみ**（`html.parser`）。外部依存は足さない。
- `colspan` / `rowspan` は格子へ広げる。広げないと列が1つずれ、
  値が隣の見出しにぶら下がる（`test_見出しのcolspanは覆う列ぶんに広げる`）。
- **入れ子の表は別の表として読む。** 外側のセルへ内側の行を混ぜない。
- 見出し行の無い表（`td` だけ）は値を並べるだけにする。作らない。
- 本文は削らない。`table_section()` は
  `MAX_TEXT_CHARS - len(本文)` と `MAX_TABLE_CHARS`(4000) の小さい方までしか渡さない。
  **本文が18,000字を埋めているページには表を1字も足さない。**
  表が読めた代わりに本文が消えると、どちらが効いたか分からなくなるし、
  減った側の損は測りようがない。
- 表の中身は本文にも入ったままにする。`parse()` の `text` は変えていない。
  片方だけにすると、いままでの結果と比べられなくなる。

### 組み直した表も、根拠の照合対象に入れる

`_attach_evidence_check()` に表テキストを足した。渡した文なのに照合対象から
外すと、**表から正しく引いた根拠が「捏造の疑い」(missing) に落ちる**。

## 効果（LLMを1回も呼ばずに測った）

`analysis/probes/check_tables.py` が、保存済みページだけを読んで前後を比べる。

```
調べたセル: 70（キャッシュ無し 0 / 採点対象ページ無し 2）
表があるセル: 28
4項目のどれかが表の中にしかないセル: 4
  うち表読みで見出しつきの表が渡るようになるセル: 4
  その項目数の合計: 6
見出しつきの表が新しく渡るセル（全体）: 28
  渡す表の総字数: 28,946
失うもの — 本文が削れたセル: 0
失うもの — 表が枠に入りきらず途中で切れたセル: 1（品川区・転入届 9,515字→3,858字）
失うもの — 表が1字も渡らなかったセル: 0
上限超過（本文＋表 > 18,000字）のセル: 0
```

中身は次の4セル。

| セル | 表の中にしかない項目 |
|---|---|
| 千代田区・児童手当の申請 | 窓口オンライン可否・期限 |
| 渋谷区・児童手当の申請 | 必要書類・窓口オンライン可否 |
| 港区・転入届 | 必要書類 |
| 練馬区・児童手当の申請 | 手数料 |

**`plans/reader-tools.md` の見積もりは5セルだった。数えたら4セル・6項目だった。**
見積もりに合わせていない。数え方が違う（あちらは68セルの観察記録を人が読んだもの、
こちらはキーワードによるスクリーニング）ので、同じ数になるほうがおかしい。

点数がどう動くかは、再測定するまで言えない。ここでは「渡せた/渡せなかった」までしか主張しない。

### 数え方の限界（正直に）

- **キーワードによるスクリーニングであって、LLMの判定ではない。**
- 練馬区・児童手当の「手数料」は、表の中の
  「マイナポータルアプリ（**無料**）」に当たった**誤検出**。
  アプリが無料という話で、手数料の答えではない。数えた4セルのうち1件はこれ。
- 逆に、`\d+円` を手数料の語に入れたら児童手当の**支給額の表**（15,000円）まで
  拾って12セルになった。金額の形は答えの形ではないので外した。
  **語の選び方で数が3倍変わる。** この数字は「表を読む価値のある上限」ではなく
  「その語で数えるとこうなる」以上のものではない。
- 品川区・転入届は表が9,515字あり、本文が14,142字で枠を食っているため
  3,858字で切れる。切れた先に答えがあるかは、この道具では分からない。

## 測定条件に必ず入れる

`table_reading`（値は `heading_value`）を `CONDITION_KEYS` に足した。
これを入れないと、**道具を足して点が上がったものが「サイトが直った」に見える**。
既存69セルは `legacy_unknown` なので `table_reading` は null。
公開済みの `web/data/scores-*.json` にも `"table_reading": null` を足した
（武器①で `link_order` を足したときと同じ手当て。足さないと
`measurement_signature()` が KeyError で落ちる）。

## やらなかったこと

- **`experiment/run.py` には渡していない。** `compose_input()` の `tables` は
  既定 `()` で、再現実験は表なしのまま。実験は `MEASUREMENT_VERSION = "exp-0.2"` の
  別系統で、本測定と条件を揃える作業は別に要る。ここでは触っていない。
- **表の中身をそのまま公開データに出さない。** いまの `quote_withheld` と同じ扱い。
- **本文から表のセルを抜かない。** 二重に渡ることになるが、抜くと
  旧データと比べられなくなる。重複ぶんの入力増は 28セルで28,946字。
