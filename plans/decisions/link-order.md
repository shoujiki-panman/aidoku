# AIに渡すリンクを、ページ順で切るか、点の高い順に並べ替えるか

Status: 決定済み（2026-08-23）
Tracks: extractor/fact_extract.py / measurement.py / analysis/check_link_order.py

## 問題

判定するAIには、ページ本文と一緒にリンクを最大40件渡している。
これまでは **ページに出てきた順の先頭40件** を渡していた。

自治体のページは、本文より前にグローバルナビ・地域案内・パンくずが並ぶ。
その結果、本命リンク（「転入届の手続き」など）が40件の外に落ちる。
「AIの道」で 30セルが *答えはリンクの先にあるのに、そのリンクを渡していない* と分かっていた。
これは自治体のページの問題ではなく、**こちらの渡し方の問題**（blame = ours）。

## 決定

`score_link`（探索側で既に使っている点付け。強い語×10 / 弱い語×3 / URLの手がかり×4 /
除外語 −8 / PDF −2）を抽出側にも流用し、**点の高い順に並べ替えてから40件で切る**。

- 件数は40のまま増やさない。入力を増やすと、点が上がった理由が
  「並べ替えのおかげ」なのか「単に多く見せたから」なのか分からなくなる。
- 同点はページに出てきた順を保つ（Python の sort は安定）。再現できる並びにするため。
- 手続き名が `crawler/targets.json` に無ければ並べ替えない（`keywords_for` が None）。

## 効果（LLMを1回も呼ばずに測った）

`analysis/check_link_order.py` が、保存済みページだけを読んで新旧の40件を比べる。

```
調べたセル: 68（キャッシュ無し 0）
40件の中身が変わったセル: 27
手続き名を含むリンクを、新しく渡せるようになったセル: 27
そのリンクの総数: 110
逆に渡せなくなった（手続き名つき）: 0
```

例: 世田谷区・粗大ごみ 0→14件、品川区・粗大ごみ 0→5件、港区・転入届 5→9件。
**渡せなくなったものは0件**。つまり片側に損のない変更。

点数がどう動くかは、再測定するまで言えない。ここでは「渡せた/渡せなかった」までしか主張しない。

## 測定条件に必ず入れる

`link_order`（値は `score_desc`）を `CONDITION_KEYS` に足した。
これを入れないと、**道具を足して点が上がったものが「サイトが直った」に見える**。
既存69セルは `legacy_unknown` なので `link_order` は null。旧データと新データは
`measurement_signature` が違うため、`attribution()` は自動的に unknown を返す。
