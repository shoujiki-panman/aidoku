# 画面を直すときの物差し

Status: 採用（2026-09-08）
出典: 「いいUIとは — 初心者向けに事例をもとにUIデザインを分解」（原 佑一）
https://speakerdeck.com/yuichi_hara7/ii-ui-toha-shoshinshamuke-ni-jirei-o-moto-ni-ui-dezain-o-bunkai

## Problem

画面の直し方が「なんとなく見づらい」で決まっていた。**直す前と後で、
何が良くなったかを言えない。** 言えないものは、次の人が戻してしまう。

## Decision

**3つの原則**で見る。どれに当たるかを、直す理由として毎回書く。

| 原則 | 問い |
|---|---|
| 発見できる | 何をすればいいか、一目で分かるか |
| 予測できる | 押す前に、何が起きるか想像できるか |
| 学習できる | 一度使えば、次から説明なしで使えるか |

そのうえで**3つの疑い**をかける（資料のATMの例）。

1. **なくても伝わる要素が無いか** — 同じことを2回言っていないか
2. **どちらがメインのアクションか、一目で分かるか** — 主役より目立つ脇役が無いか
3. **認識したい順番が逆になっていないか** — 読み手が知りたい順に並んでいるか

## 2026-09-08 に当てた結果（`web/fix.html`）

| 疑い | 現物 | 直した内容 |
|---|---|---|
| 順番が逆 | 画面の一番上が「値はこちらでは埋めません」＝**できないことの宣言**。担当者はまだ何もしていない | 免責は結果の下へ（消していない）。先頭は操作 |
| 順番が逆 | カードの1行目が「採点したページ（URL）」。知りたいのは**何が抜けているか** | 抜けている項目 → どう書くか → なぜ → ページ、の順に |
| なくても伝わる | 見出し「区を選ぶ」＋ラベル「自治体」＋選択肢「区を選ぶ」で3回 | 見出し「どの区を直しますか」1つに。ラベルは読み上げ用に残す |
| 予測できない | 区を選ぶまで画面が真っ白。何が出るか分からない | 選ぶ前に「何が出るか」の見本を3行 |
| 予測できない | 「3/4」に単位が無い | 「届いた項目 3/4」 |

`web/index.html` は地図の凡例が**地図の下**にあった（色の意味を知る前に地図を見る
ことになる）ので、地図の上へ移した。

## やらなかったこと

- **右下の「AIに渡す（ChatGPT）」の位置** — 全ページ共通の部品で、担当者向け画面では
  主役より目立つ。**だが住民向けでは主役に近い。** 片方の都合で共通部品を動かさない
- **3手続きに同じ直し方が3回出るのをまとめる** — 「どれを先に直すか」の判断が要る。
  順番の是正とは別の決定なので、混ぜない
- **ヘッダの「都知事杯オープンデータ・ハッカソン2026 応募作品」** — 提出物としての
  文脈なので、読み手の都合だけで動かさない
