# 添付（PDF / Word）を読むために外部ライブラリを入れるか

Status: 決定（2026-08-27）
Tracks: [`plans/read-through.md`](../read-through.md) ③ / Issue #148

## 問題

探索は転入届だけで非HTMLを10本見つけているが、`is_non_html_url` で弾いていて
**1本も開いていない**。弾いた理由もどこにも残っていない。

PDF を確実に読むには外部ライブラリ（`pdfminer.six` / `pypdf`）が要る。
だが CLAUDE.md は **「作品本体は Python 標準ライブラリのみで動く方針は変えない」**。

## 決定

**方針は変えない。標準ライブラリで読めるものだけ読み、読めないものは理由を残す。**

| 形式 | 手段 | 実測（転入届10本） |
|---|---|---|
| `.docx` / `.xlsx` | `zipfile` + XML | **3/3 読めた** |
| `.pdf` | `zlib` + テキスト演算子 | **0/7 読めた** |

読めなかった7本の理由:

- 6本 日本語の地の文にならない（CIDフォント。字形の対応表が本文中に無い）
- 1本 テキスト演算子が無い（画像PDFかアウトライン化）

## なぜライブラリを入れなかったか

1. **入れても点は動かない。** 10本すべて様式（委任状・住民異動届出書・本人確認書類）で、
   **手数料は載らない。** 効くとすれば「必要書類」だが、委任状の様式に必要書類の
   一覧は書かれていない（読めた3本を実際に読んで確認した）
2. **「読めない」も測定結果である。** 住民のAIも同じPDFを読めない。
   こちらだけライブラリで読めるようにすると、**住民の体験から離れる方向にずれる**
3. 方針を曲げるのは、点が動くと分かってからでよい

## 見送りを取り消す条件

**必要書類・期限で、PDFの中にしか無い項目が実際に見つかったとき。**
そのときは `non_html_reading` を `pdf_text` から変えて、条件として記録した上で入れる。

## 途中で1つ間違えた（記録）

「文字化けを本文と呼ばない」ための関門を、最初 **「英数字か日本語が2割あるか」** で書いた。
**素通しした。** 実物2本が「読めた」で抜けてきた:

- `ja-JP    en-US ja-JP …` の繰り返し（68,038字。PDFの言語タグ）
- `n�Kujvz}�r�L…` の文字化け（111,553字。CIDフォント）

どちらも `isalnum()` が真になるので、割合の関門を素通りする。
**仮名を数える**形に直した（言語タグにも文字化けにもほぼ現れない）。両方テストで固定。

**関門は、実物に当てるまで効いているか分からない。**

## 決定を取り消す（2026-08-28）

**見送りの理由が2つとも崩れた。**

### 理由①「住民のAIも同じPDFを読めない」→ **誤り**

ChatGPT も Claude も PDF を読む。**読めなかったのはうちの読み取り器だけ**だった。
つまりあの判断は、**区の落ち度ではなくこちらの落ち度**を測っていたことになる。
これはこの作品がずっと潰してきた誤りと同じ形である。

### 理由②「外部ライブラリが要る」→ **要らなかった**

字形→文字の対応表（**ToUnicode CMap**）は **PDFの中に入っている**。7本中6本にあった。
使っていなかっただけ。**標準ライブラリのみで読める。**

3つ間違えていた:

1. **Flate圧縮のストリームしか見ていなかった。** 対応表は**非圧縮の平文**で入っている
2. **`(…)` しか見ていなかった。** 日本語の本文は **`<16進>`** で書かれる
3. **埋め込みフォントを本文と混同していた**（TrueTypeのバイナリにも `BT`/`Tj` の2文字が現れる）

### 結果

| 形式 | 前 | いま |
|---|---|---|
| Word | 3/3 | 3/3 |
| **PDF** | **0/7** | **6/7** |

残る1本（中野区 `ininjyou.pdf`）は本当に画像PDF。理由は残す。

そして **品川区の「本人確認書類」PDF に、HTML本文には無い必要書類が書かれていた**
（本人確認書類の一覧・原本限定・コピー不可）。`PDF内のみ` として捨てていた中身である。

### 残っている限界（埋めない）

一部の文字が落ちる（`顔写真`→`顔写`、`交付`→`交`）。

世の中の定石を調べたところ、正しい優先順は
**ToUnicode → CIDFont の CMap → 外部CMap（Adobe-Japan1-UCS2）** であり、
かつ **フォント切り替え（`Tf`）ごとに表を持つ**必要がある
（出典: https://blog.antenna.co.jp/PDFTool/archives/2006/05/tounicode_cmap.html ／
https://qiita.com/ingtk/items/9e4457d2eb313c1ad564 ）。

**いまの実装は ToUnicode だけを、文書全体で1つの表に混ぜている。**
落ちている文字の原因はここである可能性が高い。**埋めない**——
読めなかった字を勝手に作らない方針は変えない。直すなら定石どおりに直す。

## 定石どおりに直した（2026-08-28・同日）

上の「残っている限界」を潰した。**文字の欠けは 3.1% → 0%**（読めた6本すべて）。

世の中の定石（ToUnicode → CIDFontのCMap → 外部CMap／フォント切替を見る）を
実装に落とした4点:

1. **`bfrange` の配列形式** `<0509> <050A> [<578B> <5951>]` を扱っていなかった（品川区の欠け）
2. **`<16進>` を無条件に拾っていた** — 色指定やIDまで本文として読んでいた。
   文字を出す命令（`Tj` / `TJ` / `'`）の中だけに絞った
3. **フォントごとに対応表を持つ**（`/Font << /F1 N 0 R >>` → `/ToUnicode`）
4. **対応表を持たないフォントは1バイトで読む** — 中野区の114文字は `<2020…>` で、
   CIDの1コードではなく**空白2文字**だった

### フォント別だけにしたら悪化した（記録）

北区が **0% → 6.4%** に落ちた。全体表だけだと中野区が 7.5% 落ちる。
**両方を順に引く**のが正しかった。定石の優先順そのもの。**片方だけでは足りない。**

### テストの作りも間違っていた（記録）

3件落ちたが、**コードではなくテストが誤りだった**。
PDFのリテラル `(…)` に UTF-8 を入れていた。実物は1バイト系の符号化で、
日本語は `<16進>`＋対応表で書かれる。実物と同じ形（フォント資源＋`Tf`＋CMap）に作り直した。

**実物に当てないと、テストが何を守っているか分からない。**

### いまの結果

| | 最初 | いま |
|---|---|---|
| PDF | 0/7 | **6/7** |
| Word | 3/3 | 3/3 |
| 文字の欠け | 3.1% | **0%** |

残る1本（中野区 `ininjyou.pdf`）は本当に画像PDF。原理的に読めない。理由は残す。

## 読めた中身を、抽出に流す（2026-08-28・同日）

**読めるようにしただけでは、誰にも届かない。** 抽出器は依然として添付を弾いていた。

繋いだ4点:

1. `_fetch_followed_urls` — 非HTMLも `read_document` で読み、**読めたら本文として渡す**。
   読めなかったものだけ添付に残す（**理由をURLに併記**）
2. **`run_test_case` の「PDFを要求したら例外」を外した。** 読めなかった時代の名残で、
   AIがPDFを要求した瞬間にそのセルが失敗していた
3. **プロンプト** — 「PDF本文は開かない」→「**開けます**。`follow_urls` に入れてください」。
   `PDF内のみ` の意味も「開いた上で取り出せなかった」に変えた
4. `NON_HTML_READING` を `none` → **`cmap_text`**。測定条件として記録される

### Content-Type も見るようにした

リダイレクト先が `/download` のように拡張子を持たないことがある。
拡張子だけ見ると「対応していない形式」と記録され、**中身がPDFなのに形式不明**になる。
テストで実際にそうなった。`kind_from(url, content_type)` にした。

### 旧仕様を固定していたテストを書き換えた

- `test_PDFのURLをfollow指定した応答は取得前に拒否する` → **`…したら開いて読む`**
- 読めたPDFが本文として渡ることを確かめるテストを追加
- リダイレクトの件は `test_拡張子が無くてもContent_TypeでPDFと分かる` に

**テストは仕様の記録なので、仕様が変わったら書き換える。消さずに意図を残す。**
