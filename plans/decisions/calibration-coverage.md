# 較正を、転入届だけでなく児童手当と粗大ごみにも広げるか

Status: 決定済み（2026-08-23）
Tracks: scorer/golden/jidouteate.csv / scorer/golden/sodaigomi.csv / scorer/test_score.py / reports/stability_*_2026-08-23_calibration.md

## 問題

人手の正解データ（ゴールデンセット）が **転入届にしか無かった。**

```json
"by_procedure": {
  "tennyu":      {"rows": 12, "municipalities": 3},
  "jidouteate":  {"rows": 0,  "municipalities": 0},
  "sodaigomi":   {"rows": 0,  "municipalities": 0}
}
```

較正が無いと、点が動いたときに **「サイトが変わった」と「判定器が変わった」を区別できない。**
転入届で測った「ふれ幅 最大2.0点」は転入届の9項目・30スロットについての数字であって、
児童手当と粗大ごみには**一度もかかっていなかった**。それでも3手続きの点は
同じダッシュボードに並んでいた。

## 決定

**転入届と同じ形式・同じ3自治体（練馬・江戸川・八王子）で、児童手当と粗大ごみの
ゴールデンセットを作る。ただし、キャッシュに原典が無いセルは作らない。**

- 列も作り方も `scorer/golden/tennyu.csv` を踏襲する
  （`スロット名=内容|…` の必須要素、`-` は分母から外す、`expected_found=false` は要素を書かない）
- 原典は `crawler/cache/` の取得済みページだけ。**新たに外部接続はしない**
- 何を必須要素にするかは `web/data/fact-types.json` の4項目（必要書類 / 窓口オンライン可否 /
  期限 / 手数料）に従い、**1スロット1事項**（`reports/slot_audit_tennyu_2026-07-22.md` の原則）
- **数を合わせない。** 3自治体ぶん作れなければ、作れた数で出す

作れなかったセルは CSV に `#` 始まりのコメント行として理由つきで残した
（`load_golden` は `#` 行を読み飛ばす）。消すと「無い」のか「作り忘れた」のか分からなくなる。

### 作れた／作れなかった

| 手続き | 練馬 | 江戸川 | 八王子 | 行数 | 必須要素 |
|---|---|---|---|---:|---:|
| 児童手当の申請 | ○ | ○ | ✕ | 8 | 23 |
| 粗大ごみ収集の申込 | ○ | ✕ | ✕ | 4 | 13 |

- **八王子・児童手当**: 本文が「八王子市子育て応援サイト」（外部ドメイン）へ移設済みで、
  市サイト側に残るのはリンク一覧だけ。同一ホスト制限でクロール対象外のため原典がキャッシュに無い。
  抽出器が到達したページ（`p031701.html`）は**児童手当ではなく出産・子育て応援交付金**のページだった
- **江戸川・粗大ごみ / 八王子・粗大ごみ**: `discovery_*.json` の `candidates` が0件。
  キャッシュに粗大ごみの原典が1ページも無い（八王子は「くらしの情報」目次のリンク文言のみ）

3手続き × 3自治体 = 9セルのうち **6セル**（転入届3 + 児童手当2 + 粗大ごみ1）が較正済みになった。

## 効果（実測。転入届の数字に合わせていない）

`scorer/stability.py -p <手続き> --runs 5 --model claude-sonnet-5`（転入届と同条件）。

| 手続き | LLM判定した項目 | 割れた項目 | 必須要素 | 割れた要素 | 合計点の最大ふれ幅 |
|---|---:|---:|---:|---:|---:|
| 転入届（2026-08-03 既存） | 9 | 0（0%） | 30 | 2（6.7%） | 2.0点（江戸川区） |
| 児童手当の申請 | 6 | 2（33%） | 23 | 3（13.0%） | **6.6点（江戸川区）** |
| 粗大ごみ収集の申込 | 1 | 1（100%） | 4 | 1（25.0%） | **2.5点（練馬区）** |

- 児童手当: 江戸川区 69.2〜75.8点（各回 69.2, 74.2, 75.8, 75.8, 75.8）／練馬区 80.0〜85.0点
- 粗大ごみ: 練馬区 57.5〜60.0点（各回 60.0, 57.5, 60.0, 60.0, 60.0）

割れたスロットは4つ。

```
江戸川区 / 必要書類 / 個人番号確認書類  : yes×3、no×2
江戸川区 / 期限     / 期限の長さと起算点 : yes×4、no×1
練馬区   / 期限     / 遅れた場合の扱い   : yes×4、no×1
練馬区   / 窓口オンライン可否 / 事前申込みの要否 : yes×4、no×1
```

**「最大2.0点」は転入届だけの数字だったと確定した。**
児童手当のふれ幅はその3倍以上ある。原因の切り分けはこれから（スロット文言か、判定器か）。
少なくとも「23区の点数のぶれは±2点」とは、いよいよ言えない。

### 較正がすぐ効いた副産物

粗大ごみ・練馬区は、LLMが判定した項目が1件しか無い。残る3項目は
**抽出器が「見つからない」と答えたのに原典には書いてある**ため、ルールで即0点になった。

| 項目 | 抽出器 | 原典（練馬区の粗大ごみページ） |
|---|---|---|
| 必要書類 | 記載なし（曖昧） | 有料粗大ごみ処理券、任意の紙、持込み時の本人確認書類 |
| 期限 | 記載なし | 「収集日当日の朝8時までに出してください」 |
| 手数料 | 記載なし（曖昧） | 「粗大ごみは有料です」「A券200円／B券300円」 |

較正が無い間、この3件は**採点されていなかった**（未採点＝合計に0点で混ざるだけ）。
判定器のぶれではなく抽出器の取りこぼしなので、直す先は `extractor/` 側。

## この記録を残す理由

較正の穴は「無い」ことが見えない種類の欠落で、点だけ見ていると気づけない。
次に `web/data/index.json` の `calibration` を読む人が、
**6セルは較正済み・3セルは原典がそもそもキャッシュに無い**という状態を
数え直さずに済むように、ここに置く。
