## 2. 「AWS必須」の正体

事前に「AWSデプロイ前提と読める」と書かれていましたが、**その読みは半分正しく、半分は回避できました。**

公式手順の `sh scripts/run.sh -dev` は、中で必ず `scripts/setup-env.sh` を通ります。その中身の実質1行がこれです。

```
aws cloudformation describe-stacks --stack-name GenerativeAiUseCasesStack${env} --output json
```

**デプロイ済みのAWSスタックから、設定値28個を引っ張ってくる**のです。これがAWS必須の正体でした。

ただし、リポジトリのpackage.jsonをよく見ると、**このスクリプトを通らない起動口がもう1つ用意されていました。**

- `web:devw` ← 公式手順が使う方。setup-env.sh を通る＝AWS必須
- `web:dev` ← **末尾の w が無い方。AWSを一切呼ばない**

なので、`.env.local` に設定値を手書きして `web:dev` で起動する、という抜け道が通りました。AWSがやっていた「設定値を配る」仕事を、手書きファイルで肩代わりしただけです。

## 3. 壁になったもの、正直に

### 壁1: 認証（回避したが、ソースを5行いじった）

源内は全画面がCognito認証の内側にあります。**開発用のバイパスやモックは用意されていません**（`msw`, `VITE_APP_MOCK`, `bypassAuth` などを全部grepして0件でした）。

なので、`AuthWithUserpool.tsx` に5行だけ足して、ローカルのときだけ認証ゲートを素通りするようにしました。

```
if (import.meta.env.DEV && import.meta.env.VITE_APP_LOCAL_AUTH_BYPASS === 'true') {
  return <>{children}</>;
}
```

**これは本家には無い改変です。** 変更したファイルは1つだけで、`git diff` で全部見えます。デモで説明するときは「認証まわりだけデモ用に手を入れている」と正直に言える範囲に収めてあります。

（ちなみに `/signed-out` というページだけは、改変なしでも認証なしで開けます。仕様としてそう作られていました。）

### 壁2: チャット画面は動きません（これは諦めるのが正解）

`/chat` は「予期しないエラーが発生しました」になります。エラー全文はこれです。

```
TypeError: Cannot read properties of undefined (reading 'includes')
    at getPrompter (src/prompts/index.ts:4:14)
    at src/hooks/useChat.ts:75:23
The above error occurred in the <ChatPage> component.
```

直接の原因はモデルIDを空にしているからですが、**仮にそこを埋めても動きません。** チャットの通信部分（`chatApi.ts` の `predictStream()`）は、Cognitoで一時的な鍵を発行してAWS Lambdaを直接叩く作りになっていて、ローカルの偽サーバーでは原理的に置き換えられないからです。

これは悪い話ではなく、**むしろ収穫**です。「源内で見せるならチャットではなくAIアプリ画面が主戦場」という判断が、想像ではなく実物で裏付けられました。AI読はもともとAIアプリ側なので、影響はありません。

### 壁3: 源内の本物のバックエンドはローカルでは動かせない

`packages/cdk` にはCDKの定義とLambdaのソースしか入っておらず、ローカル実行用の仕組み（SAM localのtemplate等）が同梱されていません。なので**バックエンドは自作の代替サーバーで置き換える一択**です。今回はそれで目的を達しました。

代替が必要だったのは、実質たった3本のAPIでした。

- `GET /exapps`（アプリ一覧）
- `GET /teams/{teamId}/exapps/{exAppId}`（アプリ詳細＝入力フォームの定義）
- `POST /exapps/invoke`（実行）

いずれも普通のHTTP通信で、AWS専用の仕組みは使っていません。**だから差し替えが効いた**わけです。
