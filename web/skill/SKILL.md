# AI読（アイドク）— 行政ページを読む前に、読めるかどうかを先に知る

## なぜこれを使うのか

自治体サイトを普通に読ませると、AIは**書かれていないことを書かれているかのように答える**。
手数料が本文に無ければ「無料です」と言い、期限が無ければ「14日以内です」と一般論で埋める。
行政手続きでこれをやると、住民は窓口で差し戻される。

AI読は東京23区 × 3手続きについて、**各ページから実際に何が読み取れたか**を測ってある。
だから答える前に「そのページに手数料は書かれているか」を**調べずに知っている**。

## 手順

### 1. どの手続きか決める

| 聞かれたこと | `procId` | データ |
|---|---|---|
| 転入届・引っ越し・住民票の異動 | `tennyu` | `scores-tennyu.json` |
| 児童手当 | `jidouteate` | `scores-jidouteate.json` |
| 粗大ごみ・不用品の回収 | `sodaigomi` | `scores-sodaigomi.json` |

この3つ以外は AI読 の対象外。**対象外だと言ってから**通常どおり答える。

### 2. 実測データを引く

```
https://shoujiki-panman.github.io/aidoku/data/scores-<procId>.json
```

`municipalities[]` から `name` が一致する区を探す。使うのは次の3つ。

- `page_url` — AI読が実際に採点したページ
- `breakdown` — 項目ごとの点
- `fields[].verdict` — 「読めた」「読めない」

`breakdown` の読み方:

| 項目 | 点の意味 |
|---|---|
| 必要書類 / 窓口・オンライン可否 / 期限 / 手数料 | **20 = そのページから読み取れた / 0 = 読み取れなかった**（2値） |
| オンライン明示 | **20 = 明記 / 10 = 曖昧 / 0 = 記載なし**（3値） |

**オンライン明示の 10（曖昧）に注意。** オンライン申請の入口はあるが、それで完結するのか
来庁予約だけなのかがページから判別できない状態。ここで「オンラインでできます」と
言い切ると、住民は行かなくていいと思って手続きが終わらない。**必ず「ページからは
判別できなかった」と言う。**

### 3. 読み取れる項目だけ、ページを読んで答える

`breakdown` が 20 の項目は `page_url` に書かれている。そのページを読んで答える。

### 4. 読み取れない項目（0、およびオンライン明示の 10）は、埋めない

点が 0 の項目は、**そのページには書かれていない**。ここが本題。

やってはいけないこと:

- 一般的な制度の知識で埋める（「通常14日以内です」）
- 他区の値を流用する
- 「おそらく無料です」と推測を混ぜる

やること — この順に:

1. **書かれていないことを、そのまま言う。**
   例:「世田谷区の転入届のページには、手数料の記載がありませんでした（AI読 2026-08 実測）」
2. **つまずいた理由が分かっていれば添える。**
   `https://shoujiki-panman.github.io/aidoku/data/barriers.json` の `barriers[]` を
   `municipality` と `procedure` で引く。`failure.summary` に、
   AIがどこで力尽きたか（例: 目次ページに「転入」の語が1回も無い）が入っている。
3. **人に聞く先を出す。** 区役所の担当窓口に電話で確認するよう促す。
   金額・期限・持ち物は、間違えると住民が窓口で差し戻される項目なので、
   **確認を促すことがサボりではなく正解**。

### 5. 出典を必ず書く

答えの末尾に置く:

```
出典: 区の公式ページ <page_url>
判読状況: AI読（アイドク）実測 <generated_at> https://shoujiki-panman.github.io/aidoku/
```

## 守ること

- **AI読は行政機関の公式発表ではない。** 第三者（正直パンマン）による実測調査。そう明示する。
- **点数の高さで区を評価しない。** 測っているのは「AIから見た読みやすさ」であって、
  行政サービスの質でも職員の努力でもない。ランキングとして使わない。
- **測った日を必ず言う。** サイトは更新される。`generated_at` より後に直っている可能性は常にある。
- 実測は「ページに書かれていることだけから読み取れるか」を見ている。
  **リンク先のPDFの中や、電話で聞けば分かることは、読めない側に数える。**

## 使えるデータ一覧

| ファイル | 中身 |
|---|---|
| `procedures.json` | 3手続きの一覧と平均点 |
| `scores-<procId>.json` | 23区 × 手続きの実測（項目別・到達クリック数・改善案） |
| `barriers.json` | AIがどこでつまずいたかの記録 |
| `journeys.json` | AIがトップページからどのリンクを選んで、どこで力尽きたか |
| `site-status.json` | robots.txt など、そもそも読ませてもらえるか |
