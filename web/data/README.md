# 公開データについて

AI読（アイドク）が測った結果です。**使うのに許可は要りません。**
ただし、混ざっているものが2種類あるので、そこだけ先に書きます。

**AI（プログラム）から読むなら、この文章ではなく [`index.json`](index.json) を見てください。**
どのファイルに何があり、件数と生成日時、どこまで測ってあり、どの手続きに較正が無いかが、
機械可読な形で入っています。この README は人間向けの散文です。

### 自治体サイトの実文は、いま載せていません

**`fields[].agent_value` は、2026-08-18 から空にしています**（`quote_withheld: true`）。

以前は判定の根拠として、各区の公式サイトの文を1件あたり最大200文字・**124か所／計10,708文字**
掲載していました。2026-08-17 の事務局案内「データの利用許諾についてのお願い」で、

- **都庁以外の自治体のデータは、利用者自身で利用規約の確認・許諾申請が必要**
- **「引用」は「自分の作品が主役で、引用部分はあくまで補足」の関係が必要**

と示されたため、**各区の利用規約を確認できるまで載せない**ことにしました（Issue #100）。

**点数・判定・改善案・集計は一切変わっていません。**「どの項目が読み取れたか」は
`verdict` と `points` でそのまま分かります。**実際の文面は各区の公式ページ（`page_url`）で
ご確認ください。**

### `site-status.json` — 見張りの記録

**点数ではありません。**「そのページが前回取得時から変わったか」だけを、条件付きGET
（`If-None-Match` / `If-Modified-Since`）で確かめた結果です。**本文は読んでおらず、
点数の測り直しもしていません。**

| キー | 意味 |
|---|---|
| `checked_at` | 確認した時刻 |
| `summary.headline` | 人が最初に読む1行 |
| `items[].changed` | `true`=変わった（測り直しが必要）／`false`=変わっていない／**`null`=判定できなかった** |
| `items[].gone` | `true`=**ページ自体が無くなった**（HTTP 404 / 410）。`changed` の内数 |
| `items[].status` | `304`=変わっていない／`200`=変わった／`404`・`410`=消えた／`0`=確かめられない |
| `items[].reason` | なぜその判定になったか |

**`changed: true` は「悪くなった」という意味ではありません。**「測り直しが必要」という意味だけです。

判定は2通りです。

1. サーバーが `ETag` / `Last-Modified` を返すサイト（23区中21区）→ **条件付きGET**。
   変わっていなければ 304 が返り、本文は転送されません
2. どちらも返さないサイト（渋谷区・品川区。CloudFront配下の動的生成ページ）→ **本文の指紋**で比較。
   生HTMLではなく**抜き出した本文**から作ります。生HTMLには検索ウィジェットの
   リクエストごとに変わるIDが入っていて、中身が同じでも毎回別物になるためです（2026-08-17実測）

**404 / 410 は「判定できない」ではなく「消えた」として扱います**（`gone: true`）。
採点したページが返らなくなるのは、公開している点数の根拠URLが切れるということなので、
いちばん重大な変化です。一方 5xx（サーバー側の一時的な事情）や 403 は、消えたと決めつけません。

⚠️ それでも `changed: null`（判定できない）になることがあります。前回の記録が無い、
robots.txt で許可されていない、5xx が返った、通信に失敗した、などの場合です。
**判定できないときに「変わった」とは書きません。**

## 列の意味

### ファイルの先頭

| キー | 意味 |
|---|---|
| `generated_at` | このファイルを書き出した時刻（UTC・ISO 8601）。**測った日ではない** |
| `procedure` / `procedure_id` | 手続きの名前とID |
| `question` | 画面表示用の会話文。測定用の質問はextract JSONの`test_cases[]`にfact_type単位で残る |
| `phase` | 対象の範囲（`23区`） |
| `n_municipalities` | 件数 |
| `measurement` | 測定条件・互換性・自治体ごとの実行時刻（下記） |
| `summary` | 全体の集計（下記） |
| `municipalities` | 自治体ごとの結果（下記） |
| `disclaimer` / `license` / `sources` | 但し書き・ライセンス・出典 |

### `measurement`

| キー | 意味 |
|---|---|
| `recording_status` | `recorded`（条件記録あり）/ `legacy_unknown`（記録開始前） |
| `comparison_status` | `compatible`（条件一致）/ `legacy_unknown`（比較できない） |
| `measurement_version` / `prompt_version` | 測定方法とプロンプト本文の版 |
| `follow` / `max_follow` | リンク追従を有効にしたか、その上限 |
| `max_depth` / `beam` / `max_fetches` | 探索条件 |
| `max_text_chars` / `max_links` | AIへ渡す本文・リンクの上限 |
| `model` / `model_version` | 実行手段と指定モデル |
| `run_at` / `discovery_run_at` | 含まれる抽出・探索実行時刻の一覧 |
| `runs` | 自治体ID・モデル・実行時刻の対応表 |

`run_at` だけが違う結果は同じ条件として集計できる。その他の条件が1つでも違う場合、
`export_dashboard.py` は公開JSONを書かずに停止する。新しい記録と `legacy_unknown` も混ぜない。

現在の公開23区データは記録開始前に測ったため `legacy_unknown`。現在のコード値を
過去の実測値として後付けしていない。

### `summary`

| キー | 意味 |
|---|---|
| `average` | 合計点の平均（0〜100） |
| `max` / `min` | 最高点・最低点 |
| `full_marks` | **4項目すべて**が読めた自治体の数（オンライン明示は数に入れない） |
| `zero` | 合計0点の自治体の数 |
| `fee_missing` | 手数料が読めなかった自治体の数 |

### `municipalities[]`

| キー | 意味 | 取りうる値 |
|---|---|---|
| `id` | 自治体ID（このプロジェクト内でだけ通じる） | `setagaya` など |
| `lg_code` | **全国地方公共団体コード（6桁）** | `131121` など。**他のデータと繋ぐならこれを使う** |
| `name` | 自治体名 | `世田谷区` など |
| `total` | 合計点 | 0〜100 |
| `breakdown` | 項目ごとの点 | 下記 |
| `hops` | トップページから何クリックで着いたか | 1〜3、`null`（不明） |
| `page_url` | 採点したページ | URL |
| `followed` | 追加で読んだリンク先 | 0〜2件の配列。**空配列は「追わなかった」** |
| `fields` | 項目ごとの詳細 | 下記 |
| `improvements` | 改善案 | 下記 |
| `notes` | なぜ読めないかの観察記録 | 文字列。**空文字のことがある** |
| `page_status` | **対象の手続きのページを採点できたと言えるか** | 下記 |

### `page_status`

**これは自治体の評価ではありません。こちら側が確認できているかどうかの記録です。**

| `code` | 意味 |
|---|---|
| `facts_found` | 4項目のうち1つ以上を読み取れた。対象の手続きのページを採点していると考えられる |
| `target_unconfirmed` | **4項目が1つも読み取れなかった。** 区のページに書かれていないのか、こちらが別のページを採点したのかを、この結果からは区別できない |

`target_unconfirmed` は**区の不備を意味しません。** 公開3手続き69組のうち4項目とも読めない18組は、
17組までが `notes` に「別の手続きのページ」「索引ページ」と書かれています
（例: 台東区の児童手当はこども園の預かり保育の案内、足立区の粗大ごみはリサイクル実績の統計ページ）。
**こちらの到達失敗である可能性が高く、測り直しが必要な状態です。**

判定は `notes` の文面を解釈せず、**読み取れた項目が0という構造だけ**で決めています。
`METHOD.md` §4-7 の「0点のうちどこまでが道具の制約かは、切り分けていない」に対応する印です。

### `breakdown`

キーは5つ。**`必要書類` `窓口/オンライン可否` `期限` `手数料` は 0 か 20 の2値です。**
中間の値は出ません。だから**判定が1つ変わると20点動きます。**

`オンライン明示` だけ 3値 — `20`（明記）/ `10`（曖昧）/ `0`（記載なし）。

### `fields[]`

| キー | 意味 | 取りうる値 |
|---|---|---|
| `field` | 項目名 | 上記4つ |
| `verdict` | 判定 | `読めた` / `読めない` |
| `points` | 点 | `20` / `0` |
| `agent_value` | AIが読み取った文。**いまは常に空**（上記のとおり掲載していない） | 空文字 |
| `quote_withheld` | `true`=読み取れたが、実文を伏せている | `true` / `false` |

**実際の文面は `page_url`（各区の公式ページ）でご確認ください。**

### `improvements[]`

読めなかった項目にだけ出ます。全部読めた自治体では**空配列**。

| キー | 意味 |
|---|---|
| `field` | 直す項目 |
| `gain` | 直すと増える点（20、オンライン明示は 10 か 20） |
| `reason` | 何をどう書けばよいか |

## 欠損の扱い

- **`lg_code` が `null`** → コードを付けられなかった自治体。**行を落とさず残してある**
- **`hops` が `null`** → 到達の記録が取れなかった。**0クリックではない**
- **`agent_value` が空文字** → **読み取れなかったとは限りません。**
  読み取れたかどうかは `verdict` を見てください。`quote_withheld: true` なら、読み取れたが実文を伏せている状態です
- **`followed` が空配列** → 追加のリンクを読まなかった。**リンクが無かったとは限らない**
- **`notes` が空文字** → 観察記録が無い。読める場合はたいてい空
- **`measurement.recording_status` が `legacy_unknown`** → 条件が同じという意味ではない。
  比較に必要な記録が残っていない

## 測り方と、揃っていないところ

**測り方は [`../../METHOD.md`](../../METHOD.md) に1枚でまとめてあります。**
条件が揃っていない箇所も**そこに全部書いてあります。**使う前に読んでください。

特に:

- **転入届だけ、23区を同じ日に測っていません**（2026-07-21 に3件・07-22 に20件・08-05 に1件）
- **点数のぶれ幅は測っていません。**各1回の判定です
- 各項目は2値なので、**判定が1つ変われば20点動きます**

## 更新について

**点数（`scores-*.json`）は手で回しています。**自動では測り直しません
（LLMを使うため。`generated_at` を見て、古ければ古いものとして扱ってください）。

**`site-status.json` だけは毎朝自動で更新されます。**「ページが変わったか」の確認は
条件付きGETだけで済むので毎日回せます。変わっていれば測り直しが必要という合図で、
点数そのものは前回測ったときのままです。

## history/ — 時系列（追記のみ・書き換えない）

これまで `scores-*.json` も `site-status.json` も毎回上書きで、過去の値がどこにも
残っていなかった（履歴は git のコミットにしかなかった）。ここに追記で貯める。

| ファイル | 1行の単位 | 誰が書くか |
|---|---|---|
| `history/scores.jsonl` | 手続き1つぶんの書き出し1回 | `analysis/export_dashboard.py`（人が測り直したとき） |
| `history/site-status.jsonl` | 見張り1回 | `crawler/check_pages.py`（毎朝 GitHub Actions） |
| `history/measurements.csv` | 1観測（自治体 × 手続き × 項目） | `analysis/export_timeseries.py` |

`scores.jsonl` は点数と `page_status` だけを持ち、**生の引用は持たない**（公開データの
方針に合わせる）。`site-status.jsonl` は **変化のあったものだけ**を持つ（変化なしは
`summary` の数で足りる）。

### ⚠️ 日付は3つあり、意味が違う

| 名前 | 意味 |
|---|---|
| `measured_at` / `measured_on` | **実際に測った時刻**。記録が無ければ `null`（CSVでは空欄） |
| `generated_at` / `exported_at` / `exported_on` | `scores-*.json` を**書き出した**時刻 |
| `recorded_at` / `recorded_on` | その履歴行を**記録に残した**時刻 |

**いま配信しているデータの `measured_at` は全件 `null` です。** 測定条件を記録し始める
前に測ったもので、実際に測った時刻がどこにも残っていないためです
（`extractor/out/*.json` は全件 `recording_status: legacy_unknown` で `run_at` が `null`、
`crawler/out/*.json` には `measurement` そのものがありません。2026-08-23 に確認）。

以前はここに書き出し時刻を入れて `measured_on` と呼んでいました。書き出しを流し直す
だけで「別の日に測った」記録が増えるため、**測り直した瞬間に日付が嘘になります。**
分からない時刻は空欄／`null` のまま出します。**それらしい値を入れません。**

測定条件を記録した回（`recording_status: recorded`）では `measurement.run_at` から
実測時刻が入り、`measured_at` が埋まります。`surveys.json` の
`measured_at_status`（`recorded` / `unknown`）でどちらかが分かります。

### ⚠️ 差を「良くなった」と読んでよい条件

点数が動いたとき、それが**サイトが直ったから**なのか**こちらの測り方が変わったから**
なのかは、区別しないと意味がない。各行が持つ `measurement_signature`（モデル・
プロンプト・探索幅などの条件）が**一致し、両方とも条件が記録済み**のときだけ
「差はサイト側」と言ってよい。

`history.attribution()` がこれを判定し、`site` / `unknown` を返す。
**数字は常に出すが、原因の断定だけを止める。**

なお 2026-08-22 より前の測定は測定条件が復元できない（`recording_status:
legacy_unknown`。METHOD.md §4-8）。したがって**既存データ同士の比較は必ず
`unknown` になる。それが正しい挙動**で、バグではない。

git に残っていた過去のコミットからの復元は `analysis/probes/backfill_history.py`
（冪等。何度流しても増えない）。

## archive.json — 過去の姿は、こちらで持たない

採点したページが**いつアーカイブされているか**だけを持つ。**HTMLのコピーは持たない。**

`analysis/export_archive.py` が Internet Archive の CDX API から引く（3秒間隔・連絡先つき
User-Agent）。実物は `wayback` のURLへリンクで渡す。

| キー | 中身 |
|---|---|
| `snapshots` | 版の数（`collapse=digest` なので、**中身が変わった回数**に近い） |
| `first` / `last` | 一番古い版・新しい版のタイムスタンプ |
| `timestamps` | 全部の版 |
| `wayback` | Internet Archive の一覧へのリンク |
| `failed` | **引けなかったURL**（0版と断定しない。相手が落ちていただけかもしれない） |

### なぜ持たないのか（Issue #99）

**ページの姿を残す仕事は、すでに国がやっている。**

- **国立国会図書館 WARP** — 2010年から国立国会図書館法にもとづき公的機関を大規模収集。
  **収集対象に地方自治体が明記されている**
- **Internet Archive** — 実測で、採点対象ページに 2010年からの版が存在した

こちらでコピーを持つと保存量が増えるだけで、**同じものを二重に持つことになる**。

### ⚠️ ここに「AIが読めたか」は入っていない

WARPもWaybackも保存しているのは**HTMLそのもの**で、そのページから手数料が読み取れたか・
期限が読み取れたかは記録していない。**後から遡って作ることもできない**（当時のページと
当時のモデルの両方が要る）。

**AI読の資産はコピーではなく、`history/` にある測定値の履歴のほう。**

### 引き直し

archive.org は時々応答しない。引けなかったものだけ引き直せる（取れている分は消えない）。

```bash
python3 analysis/export_archive.py                # 全部
python3 analysis/export_archive.py --retry-failed # 前回引けなかったものだけ
```
