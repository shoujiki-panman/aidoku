# 間違っていた結果の置き場（消さない）

**ここにあるのは、後から誤りと分かった測定結果です。** 判定には絶対に使いません。
**学びのために残しています。**

なぜ残すか: AI読の欠陥はどれも「間違った数字が、正しい形をして出てきた」ものでした。
**間違いの実物が無いと、次に同じ形をした数字を見抜けません。**
消すと「気づいた」という事実だけが残り、**何がどう間違って見えたか**が失われます。

> 使うときの約束: **どのファイルも入力にしない。** 読むのは人だけ。
> 現在の結果は1つ上の階層（`analysis/out/`）にあります。

## ① 手続きの説明を取り違えたまま出した虱潰し（2026-08-30）

    sweep_jidouteate.json    50項目・うち「書いていない」26
    sweep_sodaigomi.json     45項目・うち「書いていない」35
    visits_jidouteate.json   AIに読ませた1ページごとの返答
    visits_sodaigomi.json    同上

**何が間違っていたか**: `analysis/reread_field.py` の質問文が、
**転入届の説明を全手続きに使っていました。**

    {proc}とは、他の市区町村から{muni}へ引っ越してきたときに出す届出です。

児童手当にも粗大ごみにもこの一文が入っていました。除外リスト（「これは違います」）も
転入届のものでした（「転出届・転居届など、別の届出の手数料」）。

**どう見つけたか**: 墨田区の粗大ごみで、**AIの答えの中身を読んだ**からです。

    "why_not": "この本文は粗大ごみ処理手数料一覧表（品目ごとの処理券料金表）であり、
                粗大ごみ収集の申込（転入時の届出）の手数料についての記載ではない"

`visits_sodaigomi.json` にこの行が残っています。**AIはPDFを正しく読んでいました。**
手数料表だと分かった上で、「転入時の届出の手数料ではない」と却下していた。
**こちらが転入届の話だと教えていたからです。**

**学び**:

- **読めたかどうかと、聞き方が合っているかは別。** 読めても、聞き方が違えば取れない
- `found: false` の数だけ見ていたら永久に気づきません。**却下の理由文を読むこと**
- 手続きが増えるたびに、説明も除外も増える。**1つの手続きの言葉を使い回さない**
  （いまは `proc_rules()` が、知らない手続きで止まります）

**影響**: この2手続きの「書いていない」61項目は、**この記録では信用できません。**
質問文を直して測り直したものが `analysis/out/sweep_*.json` にあります。

## ② 字形の対応表を持っているのに1バイトで読んでいたPDF（2026-08-30）

    reader-compare_before-cid-fix.json   88本を外部の変換器と突き合わせた記録（修正前）

**何が間違っていたか**: フォント別の対応表が無いとき、**文書全体の対応表まで捨てて**
1バイトとして読んでいました。実測（墨田区の粗大ごみ処理手数料表）は16進1,100件が
全滅して**0字**。読めないので「その区は書いていない」と言っていました。

**どう見つけたか**: 外部の変換器（anydoc）に同じファイルを読ませたら、
「アイロン台 400 2 / カセットコンロ 400 2 …」と表のまま読めました。
このファイルには `★anydocだけ読めた` が9本残っています。修正後は3本です。

**学び**: **自分の実装しか照らすものが無いと、間違っていても気づけません。**
比較する相手を持つこと。作品本体には入れない（標準ライブラリのみの方針）ので、
検算にだけ使います → [`plans/decisions/external-reader.md`](../../../plans/decisions/external-reader.md)

## ③ 壊れたまま残っていたキャッシュ（2026-08-30）

    refetch-broken.log   60本・204MB を取り直した記録（46本が直り、14本は404等で直らない）

**何が間違っていたか**: `polite_fetch` が全応答を `write_text` で保存していた頃の
バイト列が、decode→encode の往復で壊れていました。**修正は新しく取るものにしか効かず、
既にあるキャッシュは壊れたまま**残っていました。

**学び**: **直した日と、直ったデータの日は違います。**
入出力を直したら、**既存のデータに対して検査する道具**（`crawler/refetch_broken.py`）が要ります。
